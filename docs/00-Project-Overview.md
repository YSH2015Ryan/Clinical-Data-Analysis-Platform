# 00. 项目概览（Project Overview）

## 1. 项目背景

临床科研人员（医生、医学研究者、医院科研处）普遍拥有大量临床数据（实验室化验、诊断、随访），但缺乏编程能力将其转化为可发表的统计分析结果。现有路径要么依赖统计学家手工分析（周期长、不可复现），要么使用通用工具（SPSS/R 脚本）门槛高。

GitHub 上已有大量成熟的临床机器学习开源项目（ehrapy、lifelines、scikit-survival、ClinicoPath 等），但它们面向**程序员**，以 API/库形式存在，无法被非编程用户直接使用。

**机会点**：将这些成熟开源能力包装成一个 Web 平台，让非编程用户「上传 CSV → 得到一份临床分析报告」。

## 2. 项目目标

### 2.1 总体目标

构建基于 GitHub 开源项目的临床数据分析平台（CDAP），核心链路：

```
Clinical CSV → Data Validation → Feature Processing → Multiple Models
             → Model Evaluation → Comparison → Clinical Report
```

### 2.2 具体目标（可度量）

| # | 目标 | 度量指标 |
|---|---|---|
| G1 | 非编程用户独立完成一次完整分析 | 从上传到拿到报告 ≤ 6 次点击、无需填写代码 |
| G2 | 数据问题前置暴露 | 上传后 30s 内输出可读的数据质量报告（缺失/非法/异常/重复） |
| G3 | 多模型自动对比 | 同一数据 ≥ 5 个模型并行运行，自动产出性能对比表与排序推荐 |
| G4 | 报告即产出物 | 一键导出 PDF/HTML，包含数据概况、质量、预处理、模型表现、图表、医学解释、局限性、结论 |
| G5 | 可扩展 | 新增一个模型 ≤ 1 人日（通过模型注册插件机制，不改核心代码） |
| G6 | 可扩展数据格式 | v1 支持 CSV/Excel；架构预留 FHIR/OMOP 适配层 |

### 2.3 非目标（Out of Scope）

- ❌ 不训练新的医学 AI 模型、不发明新算法
- ❌ 不做实时在线预测服务（v1 只做批量分析）；v2 可考虑模型部署为预测 API
- ❌ 不做多中心数据联邦/隐私计算（未来扩展）
- ❌ 不做临床诊断决策支持（平台定位为**科研工具**，报告附「仅供研究参考」声明）

## 3. 成功标准（项目级 DoD）

1. 用项目自带的 2 份真实测试数据（本仓库 `泛肿瘤_20221st建模样本（内部用）_20220607.xlsx` 及合成 CSV）走通全流程，产出合格报告。
2. 单元测试覆盖率后端核心模块 ≥ 80%，集成测试覆盖主链路。
3. 单机 Docker Compose 一键拉起，10 万行 × 50 列 CSV 全链路 ≤ 10 分钟。
4. 新增一个模型插件（示例：随机生存森林变体）不改平台核心代码即可注册运行。

## 4. 项目范围边界

| 维度 | v1.0 范围 | 未来版本 |
|---|---|---|
| 数据输入 | CSV、Excel（拖拽/批量上传） | FHIR、OMOP CDM、EHR 直连 |
| 分析任务 | 生存分析、二分类、多分类、回归、风险预测 | 时间序列、影像组学 |
| 模型 | 12+ 经典模型（见 07 章） | 深度模型扩展、AutoML |
| 报告 | PDF、HTML | + Markdown、Word、中文模板、期刊模板 |
| 部署 | 单机 Docker | K8s 多租户、SSO、审计 |
| 集成 | REST API | MCP Server、Agent 工作流 |

## 5. 关键约束（来自 DVPlan.md）

1. 不重新实现已有成熟算法，优先复用开源项目。
2. 模块可插拔；未来可增加新 ML 模型；未来可支持新数据格式。
3. 所有设计面向**临床科研实际使用场景**，非 Demo。
4. 发现需求设计缺陷须主动指出（已执行，见 README「核心设计决策」与 Appendix）。

## 6. 利益相关方

| 角色 | 关切 |
|---|---|
| 临床科研人员（用户） | 易用性、报告可发表、结果可信 |
| 医院信息科 | 数据不出院、部署简单、权限可控 |
| 开发团队 | 可维护、可扩展、测试完备 |
| 伦理/合规 | 数据脱敏、使用声明、审计日志 |
