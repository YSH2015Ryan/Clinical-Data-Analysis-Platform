# 05. 数据校验（Data Validation）

> 模块 2。职责：在任何分析前自动发现数据问题，输出**人可读**的质量报告与修正建议。引擎位于 `engines/validation/`，纯 Python，框架无关。

## 1. 模块卡片

| 项 | 内容 |
|---|---|
| 职责 | 编码/分隔符嗅探 → 解析 → 列类型推断 → 规则引擎 → 质量画像 → 质量报告 |
| 输入 | 原始文件（S3 uri）、可选的目标 schema 声明 |
| 输出 | `QualityReport`（issues 结构化 JSON + 列画像）、状态 VALIDATED/FAILED |
| 依赖 | pandas、charset-normalizer、Pandera（可选）、`engines/task_detection`（列语义识别复用） |
| 接口 | `validate(dataset_uri, config) -> QualityReport`；API `POST /datasets/{id}/validate` |
| 复杂度 | 中 |
| 风险 | 临床列名千奇百怪 → 语义识别需词典+规则+置信度，允许人工修正映射 |

## 2. 校验流程

```mermaid
flowchart TD
    A[读取文件] --> B[编码检测<br/>UTF-8/GBK/GB18030 自动+置信度]
    B --> C[分隔符/表头嗅探]
    C --> D[解析为 DataFrame<br/>失败→阻塞级错误]
    D --> E[列类型推断<br/>连续/分类/日期/文本/ID]
    E --> F[列语义识别<br/>Age/Gender/Diagnosis/FollowUp/Event/Label]
    F --> G[规则引擎执行]
    G --> H[列质量画像<br/>缺失率/分布/异常值/唯一值]
    H --> I[汇总 issues<br/>阻塞级 + 警告级]
    I --> J[生成修正建议]
    J --> K[落库 QualityReport]
```

## 3. 规则目录（v1）

| 规则 ID | 类别 | 级别 | 描述 | 修正建议模板 |
|---|---|---|---|---|
| RV001 | 结构 | 阻塞 | 文件无法解析（编码/格式） | 「检测到编码可能为 GBK，请转换后重传」 |
| RV002 | 结构 | 阻塞 | 空表 / 仅表头 | 「文件不含数据行」 |
| RV003 | 结构 | 阻塞 | 重复列名 | 「列 X 出现 N 次，请重命名」 |
| RV101 | 字段 | 阻塞 | 任务必需字段缺失（找不到「要预测的结果」列） | 「请补充一列要预测的结果，如『是否复发』(0/1，列名：复发/recurrence)；或在列画像中手动指定该列角色」 |
| RV102 | 字段 | 警告 | 推荐字段缺失（年龄/性别等） | 「建议补充年龄列，以支持按年龄段分层分析」 |
| RV201 | 缺失 | 警告/阻塞 | 列缺失率 > 阈值（默认 50% 阻塞、20% 警告） | 「列 X 缺失 62%，建议删除或插补」 |
| RV301 | 类型 | 阻塞 | 数值列混入非法值（如「未知」「>100」） | 「发现 N 个非数值，可在线替换为缺失」 |
| RV302 | 日期 | 警告 | 日期格式不一致（多格式混杂） | 「检测到 3 种日期格式，将统一解析为 YYYY-MM-DD」 |
| RV401 | 重复 | 警告 | 完全重复行 / 疑似同一患者重复（ID 列重复） | 「发现 N 行完全重复，可在线去重」 |
| RV501 | 异常值 | 警告 | IQR/Z-score 异常（按列类型） | 「Age 存在 3 个异常值（<0 或 >120）」 |
| RV502 | 范围 | 严重 | 临床不合理范围（内置常见检验/体征范围词典；2026-09-18 起由警告升为严重档，updateplan §16：临床不合理值须人工复核醒目呈现） | 「血钾 0.2 mmol/L 超出合理范围」 |
| RV601 | 分类变量 | 信息 | 高基数分类（唯一值 > 50） | 「列 X 唯一值 120 个，建议合并或视为文本」 |
| RV701 | 标签 | 警告 | 标签极端不平衡（<5%） | 「阳性率 2.1%，建议使用 class_weight 与 PR-AUC」 |
| RV801 | 临床模式 | 警告 | 检测到「一行一条记录」的长表结构（检验名称+结果 列组合） | 「平台分析需要『一行一个患者』的宽表，请先将各检验项目透视为列（数据准备向导，见 §8）」 |
| RV802 | 临床模式 | 警告 | 疑似药敏试验记录（判定列含 敏感/耐药/中介） | 「药敏结果不是检验指标，建议剔除或单独作为耐药史特征」 |
| RV803 | 临床模式 | 警告 | 同一检验项目存在多种单位（长表 检验名称×单位 分组） | 「单位不统一数值无法直接比较，请统一单位或使用归一化值」 |
| RV804 | 临床模式 | 警告 | 数值列存在极端值（绝对值 > 阈值，默认 1e6），疑似单位/录入错误 | 「请核对单位与录入，分析前剔除或修正」 |

> RV8xx 为「临床数据模式」规则组（2026-08-03 新增，源自真实 EHR 样本体检）：仅当对应列模式存在时触发，宽表上传不受影响。

## 5. 在线修复（Quick Fix）

校验报告的每条警告可提供**一键修复动作**（产生新 DatasetVersion，不改原文件）：

| 动作 | 说明 |
|---|---|
| 删除列 | 高缺失/无用列 |
| 删除重复行 | RV401 |
| 非法值→缺失 | RV301，预览影响行后确认 |
| 列语义重映射 | 用户下拉指定「此列 = 生存时间」 |

**阻塞级一键修复（2026-08-04 补充）**：可安全自动化的阻塞（RV201 高缺失删列、RV301 非法值转缺失）同样提供一键修复入口，由用户自主选择「自动修复 / 手动修复源文件」。前端确认弹窗必须载明：① 自动修复的风险（如删列后该变量信息在新版本中不可恢复）；② 修复产物是**新版本文件**（存于原数据集目录下），源文件永不被修改。不可安全自动化的阻塞（RV001/RV002/RV003/RV101）不提供一键修复，按提示手动处理或走数据准备流程。

**行内修复指引（2026-08-05 补充）**：问题清单逐行给出结论——可自动修复的行显示「一键修复」按钮；不可自动修复的行必须在「修复方式」列直接写明原因与出路（如 RV101：结局无法凭空生成，引导列画像重映射或数据准备向导），禁止只给笼统提示。

## 6. 性能与边界

- 流式分块读取（`chunksize=50k`），10 万行全规则 ≤ 30s。
- 内存上限：>100 万行时异常值检测采样执行并在报告中注明。
- 所有阈值集中在 `validation_config`，项目级可覆盖。

## 8. 数据准备向导（P0-1，2026-08-03 设计定稿）

真实 EHR 导出数据多为「一行一条化验」长表（RV801 可检），与分析所需「一行一患者」宽表存在格式鸿沟。数据准备（preparation）是**校验之前**的数据组装阶段：机器做苦力，医生只做选择题。涉及医学语义的决策不自动化（结果真实红线）。

### 8.1 输入与输出

- 输入：长表数据集（化验.csv）+ 诊断表数据集（诊断.csv），同项目内按患者 ID 列关联
- 输出：**新宽表数据集**（`source_type='prepared'`，一行一患者，结局列固定命名 `label`(0/1)），走正常校验/分析流程
- 引擎：`engines/preparation.py`（纯函数，框架无关）；任务：`workers.prepare_dataset`；落库：`preparation_jobs`（13 章）

### 8.2 用户决策点（4+1 个选择题）

| 决策 | 选项 | 默认 | 说明 |
|---|---|---|---|
| D1 结局定义 | 诊断词条多选（引擎扫描词频 Top100 供勾选，任一命中=阳性 1） | 无（必选） | 词条经 `~`/标点归一；子串匹配（「恶性肿瘤」命中「胰腺恶性肿瘤」） |
| D2 结局判定范围 | 任一诊断记录 / 仅索引诊断 | 任一 | 科学约束：防止同一患者既在病例组又在对照组 |
| D3 索引诊断 | 首次 / 末次 | 首次 | 决定时间窗锚点（诊断日期） |
| D4 时间窗 | 诊断前 N 天（0=不限） | 30 | 仅取 化验日期 ≤ 索引诊断日期 的记录（防泄漏，硬规则不可关） |
| D5 取值策略 | 最近一次 / 均值 | 最近一次 | 窗内同一项目多次结果的聚合方式 |

### 8.3 引擎自动执行（无决策，固定规则）

1. 剔除药敏记录（判定列含 敏感/耐药/中介，RV802 同源规则，可在决策中关闭）
2. 归一化值按检验项目分组截断（默认 1%/99% 分位 winsorize，治理 RV804 极端值）
3. 同名项目多标本 → 列名加标本后缀（`葡萄糖_血`/`葡萄糖_尿`，防混淆）
4. 特征项目数上限（默认按频次取 Top 200，防稀疏爆炸）
5. 合并诊断表的 年龄/性别/索引诊断日期/label；每阶段行数变化写入 summary（可审计）

### 8.4 API（docs/14，契约变更 2026-08-03）

- `POST /datasets/{id}/preparation/preview`：扫描两表 → 列识别结果 + 诊断词条 Top100 + 计数统计 + 推荐默认
- `POST /datasets/{id}/preparation/apply`：提交决策 → 202 → worker 生成宽表数据集
- `GET /preparations/{id}`：任务状态 + 结果数据集 + summary

### 8.5 边界（v1）

- 仅产出二分类 label；生存分析所需 time/event 列的组装属未来扩展
- 单文件简单长表（无诊断表、无时间语义）仍可用预处理 DSL 的 `reshape` 步骤（06 章 §3.1），二者互补不重叠
- 产物宽表校验采用「产物模式」（`ValidationConfig.prepared_output=True`，2026-08-03 补充）：RV201 缺失率阻塞降级为警告——EHR 宽表稀疏是常态（患者未做该项目即缺失），插补归预处理管线（06 章）而非阻塞数据集；其余规则不变
